## One-line
Thin multi-provider LLM gateway: one POST API, unified response, caller-controlled model selection, cost-tier fallback when the model is omitted. Keys never leave the server.

## What it is
Not an agent platform and not a RAG engine.  
It is a **pure model access layer**. The app sends a question plus options and gets an answer. Routing, SQL, documents, and quality checks stay in the caller.

## API surface
`POST` body (caller-controlled):

- `provider`
- `model`
- `max_tokens`
- `temperature`

Behavior:

- If `model` is set → call that model.
- If `model` is omitted → walk the default cost tier until one works.
- Response shape is the same for every provider.

Default tier (cheap → expensive):

`DeepSeek → Kimi → xAI → Gemini → GPT`

## What the gateway owns
- Normalize request/response across providers
- Default fallback only for “no model specified”
- Model catalog by tier
- Pre-check that the selected model is usable
- Explicit errors for:
  - provider/model down
  - quota / rate limit
  - model not in catalog / not available
- Keep provider API keys on the server only

## What the gateway does not own
- Business flows (chat, Text-to-SQL, trip planning)
- Quality fallback (“answer is bad, try a smarter model”)
- SQL allowlist / LIMIT / dry-run
- Document retrieval

Those are application-layer jobs. Callers can go small→large, large→small, or mix models mid-flow because each request can pick provider and model.

## Resume bullets
- Designed a thin LLM gateway so product code talks to one API instead of each provider’s SDK.
- Exposed provider, model, max tokens, and temperature per request, with a single response contract across DeepSeek, Kimi, xAI, Gemini, and GPT.
- Implemented cost-tier fallback when the caller does not specify a model; left task-specific model switching to the application.
- Added model usability checks and typed errors for outage, quota, and unknown/unavailable models.
- Kept credentials server-side so clients never hold provider keys.
- Used the gateway as the model backend for an organization Text-to-SQL assistant, without putting SQL or retrieval inside the gateway.

## Interview version (short)
I built a model proxy, not an agent.  
Apps choose the model per call. If they don’t, I fail over by price.  
If a call fails because the vendor is down or out of quota, the gateway says so clearly.  
If the answer is low quality, the app decides whether to retry on a bigger model.
